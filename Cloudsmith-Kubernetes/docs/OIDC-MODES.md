# OIDC modes: static catch-all + dynamic per-namespace mapping

Cloudsmith authenticates the cluster via OIDC token exchange: External Secrets
Operator mints a short-lived Kubernetes ServiceAccount JWT and exchanges it for a
Cloudsmith token. **Which Cloudsmith service** that token represents is decided by
the OIDC provider config. This example creates **two** providers (both in
`terraform/main.tf`), modelled on the reference demo
[`cloudsmith-oidc-dynamic-mapping-demo`](https://github.com/cloudsmith-iduffy/cloudsmith-oidc-dynamic-mapping-demo).

## 1. Static catch-all (`cloudsmith_oidc.static`)

```hcl
service_accounts = [cloudsmith_service.shared.slug]
claims = {
  aud = "https://api.cloudsmith.io"
  sub = "system:serviceaccount:external-secrets:cloudsmith-token-sa"
}
```

- Trusts **one** subject — the central ESO ServiceAccount — and maps it to a
  single **shared** service.
- This is what the cluster-wide `ClusterGenerator` + `ClusterExternalSecret` use,
  so it serves **every** namespace with zero per-namespace Cloudsmith config.
- Best when all namespaces can share one pull identity. Scales to any N for free.

## 2. Dynamic per-namespace mapping (`cloudsmith_oidc.dynamic`)

```hcl
mapping_claim = "sub"          # the claim Cloudsmith routes on
claims = { aud = "https://api.cloudsmith.io" }
dynamic_mappings {             # one per namespace (generated by for_each)
  claim_value     = "system:serviceaccount:team-a:cloudsmith-pull"
  service_account = "ns-team-a"
}
dynamic_mappings {
  claim_value     = "system:serviceaccount:team-b:cloudsmith-pull"
  service_account = "ns-team-b"
}
```

- Each namespace runs ESO with its **own** ServiceAccount (`cloudsmith-pull`).
- Cloudsmith routes the token's `sub` claim to that namespace's service, giving
  **per-namespace identity and entitlements**.
- It is also an **authorization guard**: a token from `team-a` can only become
  the `ns-team-a` service. A namespace requesting another's service is rejected —
  the same anti-privilege-escalation property the reference demo highlights
  ("a staging workflow requesting production credentials receives a 401").
- Generated **at scale** with `for_each` over `var.dynamic_namespaces` (see
  [`../scale/`](../scale/README.md)).

### Routing on the namespace itself

We default `mapping_claim = "sub"` because the `sub` claim
(`system:serviceaccount:<ns>:<sa>`) is always present in Kubernetes SA tokens and
encodes the namespace. If your Cloudsmith plan supports routing on a nested claim,
you can set `mapping_claim` to the Kubernetes namespace claim and use the bare
namespace name as `claim_value` (the Terraform handles both — see
`var.mapping_claim`).

## Choosing

| | Static catch-all | Dynamic per-namespace |
| --- | --- | --- |
| Cloudsmith services | 1 shared | 1 per namespace |
| Per-namespace entitlements | ✗ (all share) | ✓ |
| Cross-namespace escalation guard | ✗ | ✓ |
| Cluster setup | `ClusterExternalSecret` (1 resource) | per-namespace SA + generator + ExternalSecret |
| Effort at scale | label namespaces | Terraform `for_each` + generated manifests |

You can run **both at once**: use the static path as a safe default for most
namespaces, and the dynamic path for the namespaces that need their own identity.
